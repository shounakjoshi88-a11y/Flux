Sandbox paths - the live 1.10.0 image runs as user gem with HOME
/home/gem (uid 1000); /home/user does not exist and is unwritable by
the sandbox user. This broke every file operation that depended on it
and misled the model via the prompt/tools paths.

- Swept all hardcoded /home/user -> /home/gem across backend source,
  the agent extension prompt, and skills/file-reading.md. No remaining
  references in runtime code or prompts.
- The Flux workdir (/home/gem/<conversationId>) is created by the
  sandbox's own user at runtime - mkdir -p works, verified via API:
  /v1/shell/exec runs as gem; /v1/file/write to /home/user/* fails with
  EACCES 13; /home/gem/* works.
- Prompt NO-HALLUCINATED-CAPABILITIES claim about "cannot download
  PDFs" was stale - documents generated in the sandbox are downloadable
  via get_generated_file. Updated to match reality (cannot access
  private DBs/private APIs, CAN deliver generated files).
- agent-extension: "NEVER install packages" no longer true - pip + pypi
  are reachable in this image; recipe replaced with "prefer the
  pre-installed stack, install only when the task genuinely needs it, do
  not reinstall the base stack."
- prompt.ts: "visual style rules" references now point at the
  VISUAL_INSTRUCTIONS section explicitly (RULES section with CHART
  blocks).

Sandbox SDK removal earlier this session exposed fabricated success;
